# Campus — 学校生活ポータル

添付の参考画面をもとに作った、えんじ色のナビゲーションとカードを使ったレスポンシブWebアプリの試作版です。スマートフォンでは上部メニュー、PC・タブレットの広い画面では左メニューになります。

## 開き方

Node.jsとnpmを使います。このディレクトリで、初回のみ依存パッケージをインストールします。

```sh
npm install
```

起動は次のコマンドです。Viteがファイルの変更を検知して画面を更新します。

```sh
npm run dev
```

`http://127.0.0.1:5180` にアクセスしてください。既存の5173のアプリとは同時に実行できます。停止はターミナルで `Ctrl + C` を押します。HTMLファイルの直接起動ではなく、このURLから開いてください。

ポート番号自体で安全性が決まるわけではありません。開発サーバーは `127.0.0.1` のみに接続を限定し、同じPCからだけアクセスできる設定です。5180が使用中の場合は、別のポートへ自動変更せずエラーで終了します。設定は `vite.config.mjs` にあります。以前のポートに保存した試作の利用登録は、このURLには引き継がれません。

本番向けファイルの生成は `npm run build`、生成結果の確認は `npm run preview`（`http://127.0.0.1:5181`）です。配信対象は `dist/` になります。Google Fontsが取得できない場合も端末のフォントで動作します。

## 今回の実装

- ホーム：日付、時間割変更、授業数、指定時刻の空き教室数、お知らせ
- 時間割：クラス切り替え、今週の時間割、休講・教室変更の表示
- 空き教室：日付・時刻・空き教室のみの絞り込み
- 利用登録：教室、日付、開始・終了、利用目的、紙への記入済み確認
- 授業・登録との時間重複チェック、登録の保存・削除
- `#register` でフォームに直接アクセス可能。GitHub Pagesのサブディレクトリにも対応

列車・備品・食堂・図書館の機能は実装していません。実際の学校の時間割が未提供なので、授業・教室・お知らせはサンプルです。サンプルの変更は本日の授業の2限・3限に適用されます。時間割変更一覧も固定のデモ内容です。

**これは公開運用前の試作です。登録はlocalStorage（同じブラウザー内）だけに保存され、他の学生の端末とは共有されません。ログイン、共有データベース、管理者画面、公開URL・QRコードの発行は未実装です。** 「空き」は登録データ上の状態であり、紙にしか書かれていない予約は分かりません。複数端末からの同時登録を安全に処理するには、共有データベース側での検証が必要です。

## 費用とおすすめ構成

2026年10月1日時点で確認した公式情報に基づく提案です。実際の料金・無料枠は利用開始時にも確認してください。

| 役割 | おすすめサービス | 説明 |
| --- | --- | --- |
| 画面をインターネットで公開 | Firebase Hosting（Spark）またはGitHub Pages | HTML・CSS・JavaScriptを配信 |
| 全員の予約・時間割を保存 | Cloud Firestore | 端末間で同じデータを参照 |
| 学生・教員のログイン | Firebase Authentication | 学校で許可されたアカウントと権限を管理 |
| AIによる開発支援 | Google AI Studio | 自然言語での開発とFirebase連携を支援 |

**最初はFirebase Hosting＋Firestore＋Authenticationの構成を推奨します。** サーバー本体の契約・OS管理は不要です。小規模の試験運用なら無料枠内に収められる可能性がありますが、利用人数だけでなく、画面を開く回数・読込件数・転送量で決まります。AI開発支援の費用とアプリ運用費は別です。

- Firestoreの無料枠：保存1 GiB、読取50,000件/日、書込20,000件/日、削除20,000件/日、外向き転送10 GiB/月。[公式料金](https://firebase.google.com/docs/firestore/pricing)
- Firebase Hostingの無料枠：保存10 GB、転送10 GB/月。Sparkで上限に達すると利用制限・停止の対象になります。[公式の上限・料金](https://firebase.google.com/docs/hosting/usage-quotas-pricing)
- GitHub Pagesは静的ページの公開サービスなので、それだけでは共有予約データを保存できません。Firestoreなどとの組み合わせが必要です。[公式説明](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)
- 無料枠を超えた場合はFirebase Blaze（従量課金）へ移行できます。定額ではないので、利用量の監視と予算通知を設定します。予算通知は支出を自動停止する仕組みではありません。[Firebase料金プラン](https://firebase.google.com/docs/projects/billing/firebase-pricing-plans)
- Google AI StudioはFirestore・Authenticationの設定や接続コード生成を支援します。生成されたアクセス制御ルールは公開前に検証します。Firebase Studioは2027年3月22日に終了予定のため、新規開発の第一候補にはしません。Firebase本体のサービスはこの終了の対象外です。[公式発表](https://firebase.blog/posts/2026/03/announcing-ai-studio-integration)

静的サイト向けの **Firebase Hosting** と **Firebase App Hosting** は別サービスです。AIツールの公開操作がApp HostingやCloud Runを選ぶ場合は、課金アカウントが必要になる場合があります。この試作には通常の静的Hostingで十分です。[公開方法の公式説明](https://firebase.google.com/docs/studio/deploy-app)

## 実運用までの手順

1. 学校と運用方法を決め、実際の教室一覧・授業時間・時間割を用意する。PDFは初回に表形式へ変換し、教員が確認する。
2. Firebaseプロジェクトを作り、Firestore・Authenticationを有効にする。
3. 現在のlocalStorage処理をFirestoreに置き換える。閲覧、学生による登録、本人による取消、教職員による編集の権限を分ける。
4. 同一教室・同一日の登録をトランザクションで検証するなど、同時登録でも重複しない方式にする。クライアントのチェックだけに頼らず、Security Rulesとエミュレーターで不正な書込・日時・権限を検証する。個人情報は公開の空き状況と分離する。
5. 公開URLを決め、`公開URL/#register` をQRコードにする。QRコードを紙の予約表の横に置く。
6. 少人数で試験運用し、登録忘れ・紙とオンラインの不一致を学生課が修正できる手順を決める。

GitHub Pagesでこの試作を公開する場合は、GitHub Actionsで `npm ci` と `npm run build` を実行し、`dist/` をPagesの公開対象に設定します。今回は公開ワークフローの追加・公開操作は行っていません。学校で実際に使うデータを入れる前に、公開範囲を決めてください。

## 検証

```sh
node --check app.js
npm test
npm run build
```

テストは時間重複、隣接する予約、週末、取消済み授業、フォーム表示のエスケープ、保存失敗の扱いを確認します。実ブラウザーでの画面検証は別途必要です。
